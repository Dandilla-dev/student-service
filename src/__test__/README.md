## Как устроены тесты

- `studentService.js` замокан через `jest.unstable_mockModule`. Роуты импортируются только после регистрации мока: с ES-модулями иначе мок не сработает.
- `server.js` в тестах импортировать нельзя: он подключается к MongoDB и вызывает `listen()`. Поэтому тест сам собирает Express-приложение из `studentRoutes` с тем же middleware и тем же обработчиком 404.

## Почему падают 4 теста Codex

| Тест | Что не так | Кто виноват |
|---|---|---|
| `accepts score 0` | Оценка 0 получает 400 вместо 204 | **Код.** В `scoreSchema` стоят одновременно `.min(0)` и `.positive()`, а 0 — не положительное число. |
| `PATCH /score… structured 404` | Тест ждёт `Student with id 1 not found`, а контроллер возвращает `student not found` | **Спорно.** Тест захардкодил одно сообщение для всех роутов, но в `addScore` сообщение действительно выбивается из общего формата. |
| `count for one name` и `no matches` | Тест ждёт, что в сервис придёт `'John'`, а приходит `['John']` | **Тест.** Контроллер намеренно оборачивает одно имя в массив. |

## Сравнение наборов

**Что у Codex было лучше:**
- больше граничных значений в валидаторе: пустые строки, `null`, `id: 0`, массив вместо объекта в теле;
- проверка на 500 для всех 8 роутов и на битый JSON для всех трёх роутов с телом;
- проверка `Content-Type` ответа и того, что `timestamp` — корректная ISO-дата;
- `expectNoServiceCalls()` проверяет, что при ошибке валидации не вызван ни один метод сервиса;
- тест на `score: '95'`: Joi принимает строку, но контроллер передаёт в сервис исходное значение из `req.body`, то есть строку.

**Чего у Codex не было:**
- ответа 404 на несуществующий роут и на неподдерживаемый метод;
- обёртки одного имени в массив и пустого `names` в `/quantity/students`;
- теста на запрос без тела.

**Почему 68 против 39:** в основном из-за более мелкой разбивки через `describe.each`/`it.each`. Примерно на 15–20 тестов покрытие у Codex действительно шире.

## Известные баги в коде (`it.failing`)

`it.failing` проходит, пока утверждение внутри теста **падает**. Так тест документирует баг, а набор остаётся зелёным. Когда баг исправят, такой тест упадёт и напомнит, что `.failing` пора убрать.

1. **Оценка 0 отклоняется** (`studentValidator.js`, `scoreSchema`). Исправление: убрать `.positive()`.
2. **Запрос без тела проходит валидацию.** В Express 5 `req.body` равен `undefined`, если тела нет, а `schema.validate(undefined)` не возвращает ошибку. В итоге запрос доходит до сервиса, и настоящий сервис падает с 500. Исправление: добавить `.required()` к схемам или проверять `req.body` в контроллере. Та же дыра есть в `PATCH /student/:id` и `PATCH /score/student/:id`.
